## Implementation Notes (2026-10-06)

- **Retries (DF-03, resolved):** account free tier limits (Google AI Studio, 2026-10-06): `gemini-embedding-2` 100 RPM / 30K TPM. After two ingestions of 4 chunks in the same minute, AI Studio showed a peak of 8 RPM, so each text in a batch appears to count as one request (inferred). Batches of 100 would use the whole minute budget and approach the token limit, so `ingest.py` sends batches of 50 chunks and, on HTTP 429, retries only the failed batch after 30, 60 and 60 seconds. The embeddings client of `langchain-google-genai` 4.4.0 does not retry on its own (no `retry_options`). Requests per day (RPD) were not captured.
- **Replacement (ADR-003):** `PGVector.delete_collection()` + `create_collection()` + `add_embeddings()` with the vectors computed beforehand. The existing content is counted with a SQL query on the library tables (`langchain_pg_embedding` joined with `langchain_pg_collection`), since `PGVector` has no public count method.
- **Errors:** `src/errors.py` maps the exception chains (Gemini `ClientError` wrapped by `GoogleGenerativeAIError`; SQLAlchemy/psycopg `OperationalError` wrapped by `PGVector`) to the codes of spec 001. The database URL uses `connect_timeout=10` to fail fast.
- **Test PDF:** fictitious `document.pdf` (3 pages, 4 chunks), generated by `scripts/generate_document_pdf.py` (`fpdf2`, dev dependency), versioned while P-001 is open. It contains the Scenario A sentence and, on purpose, no 2024 customer count (Scenario B).
